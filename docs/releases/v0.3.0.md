# v0.3.0 — Gateway Traffic and Upstream Contracts

Status: release candidate; not published. This document is the proposed source
for the GitHub Release notes.

## Release intent

`v0.3.0` extends the gateway-as-code baseline with offline contracts for
consumer rate-limit identity, response behavior, and upstream request
configuration. It also tightens validation workflow permissions and pins its
GitHub Actions dependencies.

## Proposed highlights

- Consumer rate-limit policy can require a stable consumer identity so shared
  credentials do not accidentally collapse unrelated clients into one quota.
- Rate-limit response validation checks the client-facing status and headers
  contract.
- Upstream transport, port, host-header, and Kong service-path policies reject
  unsafe or inconsistent request-target configuration.
- The new policy helpers have focused tests and examples and run offline; they
  do not require a live Kong control plane or gateway credentials.
- GitHub Actions dependencies are pinned by commit SHA, and the validation
  workflow requests read-only repository permissions.

## Compatibility and upgrade notes

- Python 3.10 or newer remains required.
- Existing gateway CLI commands, Compose services, and declarative Kong
  configuration remain unchanged. The new policy helpers are additive and
  should be adopted explicitly in reviewed promotion workflows.
- No persisted state or gateway configuration migration is performed.

## Known limitations

- The helpers validate supplied policy and evidence; they cannot prove that a
  running Kong instance, external identity source, or upstream service follows
  the supplied contract.
- Default CI does not apply decK configuration or perform a live traffic
  promotion against a gateway.
- Safe traffic switching still depends on capacity, health checks, proxy
  behavior, and compatible backend state; the example does not guarantee
  zero-downtime operation in every environment.

## Candidate validation

Run from a clean checkout of the candidate commit:

```bash
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s tests
python3 -m kong_deck_gateway --help
python3 -m kong_deck_gateway switch green --dry-run --plan-json
bash -n scripts/deck-diff.sh scripts/deck-sync.sh scripts/switch-upstream.sh
docker compose --env-file .env.example config >/dev/null
PYTHONDONTWRITEBYTECODE=1 python3 .github/scripts/daily_pr.py --dry-run
python3 -m json.tool .github/daily-pr/backlog.json >/dev/null
git diff --check v0.2.0...HEAD
```

Expected results:

- all unit tests pass;
- the CLI help and dry-run complete without changing gateway state;
- shell wrappers pass syntax validation;
- the example Compose model resolves without starting containers;
- the completed automation backlog exits successfully without creating work;
- backlog JSON parses; and
- the release diff has no whitespace errors.

## Rollback

This release adds policy checks and CI safeguards without migrating gateway
state or declarative configuration. If a downstream workflow cannot adopt the
new checks, pin it to `v0.2.0` while the policy integration is reviewed. Do not
bypass a failed promotion or safety check to complete a traffic switch.
