# v0.2.0 — Gateway Promotion Safety Controls

Status: release candidate. Publication has not been approved. This document is
the draft source for the GitHub Release notes.

## Release intent

`v0.2.0` evolves the initial Kong and decK Compose kit into a testable gateway
promotion-control baseline. It adds deterministic, offline checks around
configuration provenance, routing ownership, upstream resilience, credentials,
and promotion evidence while retaining the existing gateway-switching entry
points.

## Highlights

- The Python CLI can produce a side-effect-free promotion plan before starting
  containers, rendering decK state, applying a sync, or changing the active
  color.
- Readiness handling now rejects stopped candidate containers rather than
  treating every non-health-checked container as ready.
- Gateway policy helpers cover route ownership, authorization scope, path and
  regex safety, request schemas, retry/idempotency behavior, and route
  shadowing.
- Evidence controls cover workspace and configuration identity, data-plane
  convergence and freshness, upstream certificates and failure domains,
  control-plane backups, credential lifecycle, and protected plugin changes.
- The unit suite validates these controls without requiring a running Kong
  deployment, registry, or production credential.

See [`CHANGELOG.md`](../../CHANGELOG.md) for the categorized change list.

## Compatibility and upgrade notes

- Python 3.10 or newer remains required.
- `python3 -m kong_deck_gateway switch`, the installed
  `kong-deck-gateway` command, and `scripts/switch-upstream.sh` remain
  supported entry points.
- `check-plugin-change` is a new additive command for validating protected
  plugin-change approval evidence.
- No persisted data or declarative Kong configuration is migrated. Operators
  should adopt the new policy helpers gradually and bind their evidence to the
  reviewed workspace and configuration digest.

## Known limitations

- The helpers validate supplied configuration and evidence; they cannot prove
  that an external collector, Kong Admin API, or upstream service is
  trustworthy.
- The Compose demo does not reproduce a production control plane, external
  secrets manager, multi-region data plane, or realistic failure load.
- Zero-downtime switching depends on sufficient capacity, correct health
  checks, a reachable proxy, compatible backend behavior, and externally
  managed persistent state. It is not guaranteed by the example alone.
- Default CI does not run a privileged live promotion, decK sync, or rollback
  against a real gateway.

## Release validation

Run from a clean checkout of the candidate commit:

```bash
python3 -m unittest discover -s tests
python3 -m kong_deck_gateway --help
python3 -m kong_deck_gateway switch green --dry-run --plan-json
bash -n scripts/deck-diff.sh scripts/deck-sync.sh scripts/switch-upstream.sh
docker compose --env-file .env.example config >/dev/null
python3 .github/scripts/daily_pr.py --dry-run
python3 -m json.tool .github/daily-pr/backlog.json >/dev/null
git diff --check v0.1.0...HEAD
```

Expected results:

- all unit tests pass;
- the CLI exposes its gateway commands and dry-run reports a promotion plan
  without writing gateway state;
- shell wrappers have valid syntax;
- the Compose model resolves without pulling or starting containers;
- completed automation backlog returns a successful no-op;
- backlog JSON parses successfully; and
- the release diff contains no whitespace errors.

## Rollback

This release adds validation and control helpers but performs no migration. If
a downstream pipeline cannot adopt `v0.2.0`, pin it to `v0.1.0` and retain the
previous switching workflow while the incompatibility is investigated. Do not
bypass a failed promotion or policy control merely to complete a rollback.
